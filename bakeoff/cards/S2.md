# S2 fan-out x3

Tests real parallelism and how the lead batches three reports.

1. t0: `three jobs, in parallel please: sort fruits.txt alphabetically, remove duplicate lines from todo.txt, and add a one-line title at the top of haiku.txt`
2. Log `event:` when each worker starts and finishes (from observe.sh or the lead's messages); note whether the lead reports each separately or once.
3. Lead reports all three ready → `merge all three`. If it reports only some, wait (stall rule) for the rest.
4. Merged → `clean up` unless already done → `end`.

Optimal: 3 workers start within seconds of each other, finish independently, one combined "all three ready" report, three merges, cleanup. Captain turns: 2.
